Section 1

What the exam covers

The exam is split into skill areas. The percentage shows roughly how much of the exam each area makes up, so spend your time to match.

Design and implement processes and communications10–15%
  • Traceability and flow of work
  • DevOps metrics and queries
  • Collaboration and communication
Design and implement a source control strategy10–15%
  • Branching strategies
  • Configure and manage repositories
Design and implement build and release pipelines50–55%
  • Package management strategy
  • Testing strategy for pipelines
  • Design and implement pipelines and deployments
  • Infrastructure as code (IaC)
  • Maintain pipelines
Develop a security and compliance plan10–15%
  • Authentication and authorisation methods
  • Managing sensitive information in automation
  • Automated security and compliance scanning
Implement an instrumentation strategy5–10%
  • Configure monitoring for a DevOps environment
  • Analyse metrics from instrumentation
Section 2

Key concepts, explained simply

These are the ideas that come up again and again. Open each one and make sure you could explain it to a friend.

Pipelines are half the exam

Build and release pipelines are 50–55% of the questions. Know YAML pipeline structure (stages, jobs, steps), templates, triggers, agents, environments with approvals, and the equivalent concepts in GitHub Actions.

Branching strategies

Trunk-based development keeps short-lived branches merged often. GitFlow uses long-lived develop and release branches. Use branch policies and pull request checks to protect main.

Deployment patterns

Blue-green switches traffic between two identical environments. Canary releases to a small group first. Feature flags turn features on without redeploying. Ring deployments widen the audience step by step.

Secrets in automation

Never store secrets in code or pipeline YAML. Use Azure Key Vault, variable groups linked to Key Vault, GitHub secrets, and workload identity federation instead of long-lived service principal secrets.

Security scanning

Shift left with dependency scanning, secret scanning and code scanning (for example GitHub Advanced Security), plus container image scanning before deployment.

Measuring DevOps

Track deployment frequency, lead time for changes, change failure rate and time to restore service. Use Azure Monitor and Application Insights for telemetry.

Section 3

Study plan

About an hour a day is enough. Adjust the pace to your experience.

  1. Week 1Processes, work tracking and source control: Azure Boards, GitHub, branching and policies.
  2. Week 2–3Pipelines: YAML, templates, agents, artifacts, testing and package feeds. Build one in Azure DevOps and one in GitHub Actions.
  3. Week 4Deployments and IaC: environments, approvals, deployment patterns, Bicep or Terraform.
  4. Week 5Security and compliance: Key Vault, identities, scanning. Then instrumentation with Azure Monitor.
  5. Week 6Practice assessments, review weak areas and redo labs end to end.
Section 4

Exam tips

  • Read every question twice. Many answers are “which service fits this scenario”.
  • Use the free practice assessment on Microsoft Learn until you score 80% or more.
  • Hands-on practice beats memorising: build what you read about in a free account.
  • Skip hard questions and come back. Unanswered questions score zero, so answer everything.
  • Check the official study guide a week before your exam in case the skills changed.
